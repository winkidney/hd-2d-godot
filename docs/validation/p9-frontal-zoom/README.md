# F/W/O 镜头距离与视野调节

下文验收与交付包对应镜头调节交付时的版本。用户随后要求提交现有结果，新增发现的38份纹理导入配置及当前校验另见[提交前校验](commit-check.md)，原交付文件未覆盖。

本轮只扩展正面运河场景。旧A/B/C/D、原素材、模型与原审阅包不变，未提交或推送。

## 使用

- F9打开镜头面板。Distance调节镜头到观察中心的距离，18–45米，步长0.5米；Field of view独立调节纵向视野角度，25–60°，步长1°。
- 游戏中滚轮向上拉近、向下拉远。打开任意调参面板、对话、自动路线、预览或展示镜头时不响应世界缩放。
- F/W/O分别保留设置。修改实时生效；点击Save lens保存当前方案，下次启动或首次切换自动载入。Load lens重新载入，Reset lens恢复本方案距离和视野默认值。重置后如要下次仍用默认值，需要再次Save lens。
- F8继续独立调整视差与跟随，原保存格式不变。Reset this camera同时重置当前方案镜头与视差，但不会自动写入本机设置。
- Run the same walking route临时恢复本方案默认镜头，结束或按Esc取消后恢复个人调节。

默认值未变：F为30m/35°，W为23m/45°，O为30m/35°。改变距离不改变俯角，也不移动道路、建筑、人物或碰撞。它不是只放大最终画面的图片缩放。

近距离和窄视野组合可能把人物、屋顶或天空裁出画面；远距离或宽视野可能露出场景边界。实际截图中，F/O的18米近景裁切屋顶，45米远景露出前方场景边缘；O在36米/48°时也已露边，并非只有最大值才出现。近景放大后人物细节偏软，这次没有重新制作精灵。完整构图与左右换侧的历史验收针对默认值，不延伸为所有自定义组合都保证同样构图。原路灯遮挡、栏杆遮腿等美术问题仍保留。

## 运行包

解压`frontal-zoom-linux.zip`后运行`frontal-canal.x86_64`。项目源码在`frontal-zoom-project.zip`，从工程使用`make frontal-run`进入新场景。原工程默认入口保持不变。

`SHA256SUMS`覆盖交付文件。`delivery-report.json`记录运行源码指纹、独立包散列与各检查结果。测试原始报告和截图在`frontal-zoom-evidence.zip`。

## 复跑

使用现有环境，不安装新依赖：

```sh
python3 tools/p9frontal/lens.py test
python3 tools/p9frontal/lens.py gpu
python3 tools/p9frontal/lens.py export
python3 tools/p9frontal/lens.py package
```

新的验证目录为`build/p9-frontal-zoom`，本机设置测试使用独立用户数据目录，不触碰日常运行偏好。原审阅录像和30秒性能采样没有重发为本次功能证据。

默认物理路线每方案25站全部通过，零跌落恢复；另在自定义O镜头下实测完整路线和Esc取消，都恢复完整镜头、偏航/平移状态、人物、时段与景深。旧场景`make test`通过，含410项P8运行检查和跨进程设置检查。独立运行包结果及同版本指纹由`delivery-report.json`给出。

执行中发现异常配置缺字段和字段类型不符会触发引擎错误，已改为先检查字段白名单和类型、再整份应用；新增测试覆盖这些拒绝路径。复核又发现细刻度滚轮会造成面板步长与实际值不一致，现按半米离散处理，并验证factor=0.25的输入。缩放后的过期状态文案也已修正。

原审阅包、录像和30秒性能数据保持历史版本，不用本轮单帧画面宣称新增性能结论。此次没有重新生成美术资产，也不改变旧A/B/C/D实现。
