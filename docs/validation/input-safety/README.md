基线为`2a3c00a`。修改覆盖驿站、参考场景、参考灰盒、正面运河四个运行入口。代码已修复，共707项无窗口输入回归通过，测试进程清理的四项回归通过。用户要求暂不弹窗，剩余窗口级全矩阵复核延期，不宣称四场景GPU验收全部完成。

## 原因与复现

相同正面运河场景独立运行时F8不退出；编辑器启动的独立游戏窗口收到F8后，游戏进程退出。把场景减为无任何脚本的Node3D，仍可复现。结果记录在本次工作目录`work/input-repro`中，不能用直接调用`scene._input`来替代这一证据。

Godot 4.7.2编辑器在调试连接建立时发送Stop快捷键，游戏把监听装到根窗口`window_input`，该信号早于游戏Viewport输入处理。匹配F8就发`request_quit`，不读取游戏的handled状态。[发送端](https://github.com/godotengine/godot/blob/4.7.2-stable/editor/debugger/script_editor_debugger.cpp#L1281-L1282)、[运行端](https://github.com/godotengine/godot/blob/4.7.2-stable/scene/debugger/scene_debugger.cpp#L112-L151)、[窗口顺序](https://github.com/godotengine/godot/blob/4.7.2-stable/scene/main/window.cpp#L2022-L2029)。

F9/F10还可能被Game View用于暂停/恢复和下一帧，不能把游戏面板绑在这些键上。[官方实现](https://github.com/godotengine/godot/blob/4.7.2-stable/editor/run/game_view_plugin.cpp#L61-L157)。没有拆引擎内部回调，也没有关闭编辑器停止功能。因此，编辑器调试时按F8仍会停止，这是保留的编辑器操作；修复的是场景错误占用这个快捷键。

旧版另有稳定复现：Ctrl+F8误开面板，Ctrl+T误切时段，Alt+H隐藏HUD，Ctrl+Esc关闭面板或取消路线，Shift+F9误开相机面板。数值框内Tab会关闭面板并隐藏HUD。旧版数字/字母的普通文本编辑和Popup优先关闭已正确，报告不把它们误记为新发现。

## 修复

| 功能 | 当前游戏键 |
|---|---|
| 视差/跟随参数 | P |
| 景深参数 | O |
| 相机比较、正面运河镜距/FOV | C |
| 展示/后处理/跟随/景深开关/远景 | G / V / F / B / K |
| 隐藏HUD/截图 | H / J |
| 界面焦点移动 | Tab / Shift+Tab |

四场景复用同一输入分发，游戏动作放在GUI之后处理。面板不接收修饰键的裸键动作，LineEdit/TextEdit内不触发场景字母/数字操作。左上方按钮提供视差、景深、相机和退出入口；驿站不显示不存在的相机面板。

Esc按弹出菜单、预览、面板、对话的顺序返回，无这些状态时显示退出确认。窗口关闭和Exit按钮也先确认；默认焦点是Keep playing，Enter保留游戏。确认Exit才退出。自动路线期间只有裸Esc取消，修饰键和重复事件不取消路线。

## 验证边界

`tests/input_dispatch.gd`通过`Input.parse_input_event`走真实Godot事件分发，共707项，四场景均运行到结尾。覆盖按下/松开/echo、修饰键组合、旧F键不再触发游戏动作、Tab、数值输入和Enter、面板互斥、Popup/预览/面板/对话的Esc顺序、退出确认默认焦点、路线锁、初始化与释放后的关闭信号连接。这里的按钮验证使用公开pressed信号，不冒充原生鼠标点击。

`tools/input_window_test.py`另启动真实Forward+窗口，通过X11向已核对归属的窗口发送键盘/按钮事件，经过Window输入和GUI处理，不直接调用场景函数。它不代表真实硬件键盘，也不抢焦点、移动桌面指针或修改编辑器设置。

驿站独立运行和编辑器启动各136项窗口级检查通过，包含P/O、文字编辑、Tab、工具栏点击和退出确认；这是中间版本证据，记录于`build/input-window/20260929-121607`。该次编辑器游戏子进程未被完整清理，已人工按确切PID清理并修复测试工具。部分早期XTest尝试在用户同时操作鼠标键盘时失败或中断，不能当作确定的产品回归结果，也没有合并成全通过。

修正后的清理按进程启动时间、pidfd句柄和隔离项目路径追踪子进程，不假定编辑器和游戏处于同一进程组。普通进程、独立会话子进程和已退出父进程都被测试，无关进程保留。额外以纯Python模拟先复现PID复用、迟到子进程两个失败，再修正为保留首次身份并有界重扫，四项回归全部通过。停止后已核对本次测试进程全部退出；修正后的完整窗口矩阵待用户允许时重跑。

### 命令

```sh
make input-test
/usr/bin/python3 tests/test_input_window_cleanup.py -v
```

这两条不弹窗口。`input-test`复制源码、隔离用户设置，写入带时间戳的`build/input-window/`目录。新输入测试单独使用已有的系统Python以取得Linux pidfd安全清理接口，不改变其他工具的解释器或安装依赖。缺少该能力时，窗口测试在创建进程前拒绝启动，不退回按PID直接发送信号。

只有用户方便窗口测试时再运行：

```sh
make input-window-test
```

它会创建真实窗口，依次测试四入口的独立启动及编辑器启动，不并发使用GPU。每个场景必须检查窗口输入结果及`cleanup.passed`，不能只看脚本退出码。若用户中途继续操作测试窗口，需重新跑受影响项。
