# P9 四方案执行日志

本轮检查点：`3b6333f`。不提交、不推送；没有安装依赖或启用 Blender MCP。

## 来源与共同资产

1. 保留原工作检查点与历史证据；读取工程约束及计划、ADR、领域索引。
2. 接入用户上传两张 PNG。保留字节散列及 RGBA 像素散列，明确素材板与历史 `ff85aae1…` 记录不同。
3. 原图直接生成 23 张 PNG，独立目录复做输出字节一致；16 个 Blender 模块重建并逐一重开 `.blend` 核对。
4. 视觉检查发现五套角色脚底原纸面灰影，限定底部18%的外部连通中性像素去除。头脸衣服主体不改变；18张纹理、16套模型及原图不变。
5. 共同背景增加六个低面数地基／铺地盒体，防止楼群下方露底；不增加碰撞，不改变道路、桥和楼梯。

## 实验和修复

1. 新建 P9 专用相机／视差／预览适配，旧场景控制器不改。四个模式独立状态，F9 切换；D 使用真实离线七视图，不伪装成相机透视。
2. 独立数学测试使用引擎 `unproject_position` 核对。最终4603项，包括偏航规则、真实精灵端点、临时预览和D图帧恢复。
3. 首次 GPU atlas 生成触发隐藏水面占位对象没有 mesh 的灯光初始化错误。增加隐藏 PlaneMesh 后重跑，21帧生成无错误。
4. 首次路线测试发现访问不存在的 `player.speed`，改为角色常量 `SPEED`。
5. 第一轮人物高度检查误用世界竖直线段，出现约4.3%差异；实际人物是朝向镜头的 Sprite3D。标定与测试改为真实48×64帧的垂直端点、pixel_size0.035、offset30；四方案中央高度一致。不是通过放宽2%阈值规避失败。
6. 只读审查发现 D 临时预览关闭后图帧继续收敛；已同步保存／恢复角度、目标角、图帧及贴片变换。
7. 路线运行期间键盘隔离，Esc 明确取消。路线结束恢复原跟随、巡游、冻结和输入状态。
8. 第一轮 GPU 图像测量：四种投影下近／焦内／远棋盘实际通过，五层视差的400次白标记测量通过0.8px阈值。正式证据另行重跑，不拿这轮未完成的人物标定报告当最终通过。
9. 首轮录像元数据校验发现电影写入器仍取项目窗口覆盖值1280×720，忽略命令行1920×1080。原录像保留在 `media-720-first-pass`；正式录制副本仅将窗口覆盖值设为1920×1080，重新导入后录制，不上采样旧片冒充1080p。
10. 主建筑宽视口夹具补齐因游戏边缘出画而不足的侧面证据；D七整数帧及3.5过渡均保留，固定脚点与深度裁切限制分别记录。
