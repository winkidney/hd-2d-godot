# Ancient 横向河街与夜空重构 · 2026-10-08

已按确认布局接入横河、低矮石拱桥、木码头、酒肆与三座民居、三个摊位、五名驻点 NPC、平面柳树和缓存夜空。本轮不提交或推送。以下验收对应当前源码，不覆盖历史素材和报告。

## 场景与兼容

- 地图仍为 X=±26、Z=−16～14。河中心 Z=2.5，宽 5.2 米；石桥中心 X=1.2，跨度 8.4 米、宽 2.8 米、最高 0.6 米。码头顶面 Y=−0.32，后岸留出接岸坡道，与小船相邻。
- 地面、水域阻挡、桥面、桥栏、码头坡道及岸界从同一布局生成。后岸建筑疏密分组，前岸横向步道连接桥头。自动路线经过两岸、桥、酒肆、三个摊位和码头，再回到起点；移动键与 Esc 可接管。
- 三棵近景与五棵背景柳树为竖直像素卡片，透明裁切与 mipmap，近景投影、背景不投影。旧三维柳树及原桥资源保留；新增低桥有独立 GLB、可编辑 Blender 源及实际重开检查。
- 掌柜、摊主、船工保留，新增食摊摊主与茶客的独立驻点颜色／法线／银饰蒙版、来源图、生成请求和对话。主角原 108 帧颜色、法线、银饰、时序及碰撞保持。
- F/W 正面镜头、角色跟随、六层视差、灯具编号与控制、schema 2 设置、比较模式和单灯隔离保留。夜晚手动调光变成 custom，保存／载入仍保留夜空。

## 夜空实现

固定种子 20261008 离线生成 4096×2048 全景：不规则银河亮区、暗尘带、18000 个不同大小／亮度星点，以及约 0.75° 弯月。月亮位于方位 15°、仰角 2.5°，保持原 F 镜头时可见天空上缘；云层会自然遮挡部分月面，W 机位也可能被云遮住。没有为突出月亮放大它或改变镜头。

运行时使用缓存 Sky／ShaderMaterial 和一张带 mipmap 纹理。横移每米约 0.005°，最大 ±0.15°，基于绝对相机位置；星点、银河、月亮一起旋转，静止时不漂移。不生成噪声、不创建逐颗星节点、不逐帧修改天空材质参数。

为保留默认景深下的小弯月与星点，在 Forward+、2×MSAA 的已解析深度上执行一个计算通道，仅将天空深度写为当前焦距。实体的深度及原景深仍保留；不新增全屏纹理、颜色叠层或几何。关闭 MSAA 时跳过保护，其他渲染路径未验收。取舍与引擎依据见 [ADR-22](../../../ADR/22-horizontal-canal-night-sky.md)。

三个 GPU 轮次与三个 CPU 轮次各自也满足预算。CPU 合计包含天空更新、渲染线程保护通道，以及整个原有焦距更新函数，因而是保守值；天空更新本身每调用平均 0.001190 ms，保护回调每调用平均 0.007832 ms。插桩数据单独保存，父子函数计时不相加。GPU 增量很小，P95 正负波动应视为测量波动，不宣称夜空提高性能。平均值与 P95 采用三轮等权平均，P95 不合并；GPU 与渲染 CPU 计时重叠，不能相加当作帧时间。旧路线约 20.1 秒，新路线约 38.48 秒，因此整体比较反映各自有效探索场景的负载，不单独证明某一资产的收益。同布局夜空 A/B 才用于归因夜空新增成本。

场景库存由 315 个 MeshInstance／444171 个三角形降为 204／136767；库存没有计入 Sprite3D 卡片的三角形，因此它是源场景几何指标，不是实际每帧总图元。实际绘制计数逐帧保存在原始样本。新场景整体 GPU 平均降低约 8.4%～9.4%，但有效路线与可见内容不同，不将其全部归因于柳树。

以新夜景第一轮的相邻 GPU 时间戳区间为例，主要时间仍为景深 0.488 ms、不透明物体 0.409 ms、局部灯阴影 0.168 ms、SSR 0.144 ms、深度预通道 0.125 ms；局部阴影对应的渲染 CPU 区间约 0.169 ms。区间包含队列等待，不是独立 shader/kernel 微基准，也不能把所有消融收益相加。后续优化优先级仍为可选低档景深、静态背景／材质整理与局部投影灯数量，不需要削减主角法线帧。

夜空纹理按 GPU 可能使用 RGBA8 的保守上界计算：4096×2048×4 字节×4/3 mipmap = 42.67 MiB，小于 48 MiB。该值是预算估算，不是驱动分配器实测；计算通道不新增全屏纹理，辐射缓存取代原 Sky 缓存。

## 首次夜空更新与反射缓存

| 夜景轮次 | 初始 Setup Sky 最大 GPU / CPU 区间 | 初始视口最大 GPU | 前 120 次绘制覆盖 |
|---|---:|---:|---:|
| new-night-r1 | 0.670816 / 8.475 ms | 2.864 ms | 0.242 秒 |
| new-night-r2 | 0.673504 / 9.569 ms | 2.623 ms | 0.334 秒 |
| new-night-r3 | 0.665824 / 8.628 ms | 3.531 ms | 0.243 秒 |

初始窗口包含前 120 次完成绘制，GPU 时间戳有异步返回延迟；这些最大值记录进入夜景后的初始化区间，不把整个视口耗时当成纯天空耗时。Setup Sky 的 CPU 区间也包含首次材料／辐射缓存更新，不能与 GPU 时间相加。Scene 的时段切换调用在首、第三轮分别为 0.342／0.348 ms；第二轮 A/B 的启用调整在该调用之后，所以不将其 0.178 ms 标为完整的夜空启用 CPU 成本。首轮记录使用已有驱动 shader 缓存，不宣称覆盖全新驱动冷编译。

三轮稳定行走期间 Setup Sky 平均约 0.0018 ms，最大区间均远低于初始约 0.67 ms。天空旋转不修改材质；夜空 shader 不依赖 TIME／POSITION／灯输入。核对与本机版本一致的 [Godot SkyRD 实现](https://github.com/godotengine/godot/blob/ed1daf0bf001b61586d9930840f2f1394092c079/servers/rendering/renderer_rd/environment/sky.cpp#L942)：这些动态输入与材质变化会触发反射更新，环境旋转用于天空与辐射采样方向。据此及持续采样结果，未发现行走导致持续重算天空反射的现象；没有把每帧都会存在的 Setup Sky 标记本身误判为每帧重建。
