# Ancient 性能数据归档 · 2026-10-08

[分析与优化方案](../../profiling-20261008.md)使用本目录的数据。[summary.json](summary.json)保存可以从原始采样重算的结果，[archive-manifest.json](archive-manifest.json)登记每个原始文件与归档文件的 SHA-256、大小及对应关系。

## 主要结果

修正后的默认黄昏、1920×1080、2×MSAA 基准，GPU 均值 2.023 ms、P95 2.364 ms，CPU 视口渲染均值 0.553 ms、P95 0.697 ms。GPU 热点为不透明物体、景深与阴影；CPU 渲染热点为局部灯的阴影裁剪和提交。

- 景深从中档降到低档，保持效果开启，GPU 总耗时降低约 15%。
- 关闭全部局部灯阴影，CPU 渲染耗时降低约 56%、GPU 约 11%。这是关闭测试的收益上限，优化时应保留关键投影。
- 共享法线开关关闭后，GPU 均值从 2.023 降到 2.011 ms，差异约 0.6%。该测试同时影响角色、NPC 和建筑，没有单独隔离角色法线；未显示角色逐帧法线是主要瓶颈。
- 场景每帧脚本更新约 0.069 ms，角色物理更新约 0.045 ms/次；父函数包含子调用，不应累加。

这些是后台离屏计算数据，未测前台显示呈现、输入延迟或启动加载。原基准的最小化休眠和 SubViewport MSAA 偏差、早期 GPU 时间戳字段单位问题均保留说明。不同测试的优化收益不能直接相加。

## 文件结构

| 路径 | 内容 |
|---|---|
| `raw/` | 42 组逐帧原始 JSON，以 gzip 无损压缩；解压字节与采样时完全相同 |
| `metadata/` | 7 份原始报告、6 份运行清单、阶段汇总、模型统计、原始检查与清理记录 |
| `snapshots/` | 当次生成的独立测试脚本与 CPU 计时副本，保持原始字节和 build 内资源引用 |
| `sources/benchmark.gd` | 当次原基准源码快照，与各运行清单中的摘要匹配 |
| `summary.json` | 从归档原始数据重算的整帧分位数、GPU 阶段、CPU 函数、逐项对照与主要结论 |
| `archive-manifest.json` | 原路径、归档路径、编码、压缩前后大小与校验和 |

采样组包含原工具三时段基准、初期有后台休眠的对照、修正后的反向对照、CPU 计时、关键项复测和两轮 GPU 阶段分析。最终收益采用 `ablation-b` 与 `confirm`，初期数据保留作方法和来源记录。

原始清单中的 `build/ancient-canal/profile-20261008` 路径是采样当时的位置，已由归档清单映射到本目录，不依赖该 build 目录继续存在。脚本快照用于审计当次行为，新的实际测量使用 `tools/ancient_canal/profile.py` 生成探针。

归档保留 78 个文件，约 45 MB 原始内容压缩至约 6.4 MB。没有保存运行日志、个人配置、着色器缓存、管线缓存或临时用户目录。

## 不使用 GPU 的数据复核

在项目根运行：

```sh
python3 tools/ancient_canal/verify_profile_archive.py
```

只使用 Python 标准库，不启动 Godot、不创建窗口、不修改归档。它检查 78 个文件压缩前后的字节摘要，验证原始报告与样本的关系、生成脚本来源、绘制计数和采样条件，重算 42 组均值与分位数、GPU 阶段及 summary，并与保存结果比较。重建 summary 可显式添加 `--write-summary`。

实际 GPU 采样与画面复核是独立事项；上述数据完整性检查不能替代新的硬件性能或视觉验收。
