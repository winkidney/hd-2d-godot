# P9 · 四种侧面观察实验

状态：工程实施与验收完成，交付待用户集中审阅。已提交检查点为 `3b6333f`；本轮没有提交或推送。四套实现全部保留，最终美术选择仍由用户决定。结果、已知视觉缺陷及性能数据见 [本轮验收报告](../../docs/validation/p9-experiments/README.md)。

## 实验与共同条件

| ID | 投影和跟随 | 侧面变化 | 视差方式 |
|---|---|---|---|
| A | 35°透视，固定朝向，平移跟随 | 相机位置变化观察真实三维建筑 | 自然基线，可调屏幕横向补偿 |
| B | A 加水平绕转 | 平移与最多±6°绕转共同观察真实侧面 | 只补偿横向平移，绕转保持自然 |
| C | 正交投影，水平绕转 | 最多±6°绕转露出真实侧面 | 正交投影下的横向补偿 |
| D | 正交投影，固定朝向 | 主建筑切换离线渲染的七个观察图像 | 独立分层倍率与多视图模拟 |

A/B/C 使用同一套模型、纹理、灯光和碰撞。D 的主建筑图集来自同一模型，碰撞继续使用三维世界；其画面只有一个深度平面，不能声称等价于三维遮挡或阴影。D 的近场道路、桥、楼梯、人物和交互点不参与背景补偿。

B/C 的偏航由角色相对出生锚点在初始相机水平轴上的位移决定：1m 死区，之后10m达到±6°，独立指数平滑率2.5/s。平移也使用初始固定轴，避免镜头旋转反过来改变跟随输入。俯角、观察半径、透视FOV保持固定。C/D 的正交尺寸按出生锚点人物高度标定，中央位置与A的屏幕高度误差目标不超过2%。

D 保留晴昼、黄昏、夜晚图集；每个图集依次包含 `−24/−16/−8/0/8/16/24°` 七个视图。相邻帧采用像素抖动过渡，不做半透明叠影。视图由相机相对建筑的水平位置选择，这是显式模拟，固定朝向正交相机本身不会因平移露出另一侧。背景近/中/远倍率默认 `0.6/0.3/0.12`，云层默认 `0.6/0.25`。

## 实施顺序

1. 原图来源接入。两张重新上传PNG保持原字节，登记文件散列、RGBA像素散列、尺寸和用途。素材板的文件散列与历史记录不同，保留差异，不声明字节一致。全幅概念图仅用于构图；原游戏截图仅供研究。
2. 原图生产链。原PNG直接裁切、透视校正、边缘连通去底、调色、像素化和图集组装。保留 `3b6333f` 的旧小图派生产物作为对照；重复构建检查输出散列。
3. 共同美术。补足建筑左右侧窗、腰线、檐口及转角；桥体、平台和市场只做一套共同调整；远景覆盖按四种相机极值检查。Blender脚本、blend和GLB同步保留。
4. 四方案接入。P9独立相机、视差和预览适配，旧场景继续使用既有控制器。F9选择A/B/C/D，显示当前投影、偏航、视差和D图帧；提供恢复当前方案默认值及统一行走路线。
5. 公平对照。先关闭景深并冻结云、水，固定同一时段比较机制；再恢复动态和景深，覆盖三时段。手动切换保留玩家位置、时段和景深；相机平滑状态按新模式重建。
6. 回归和交付。修复失败项，保留原始失败日志及重跑记录；生成四段同路线视频、同步四宫格、截图、性能样本、独立Linux包、完整源码和SHA256。

各方案的视差设置在内存与本机保存路径上隔离。切换前停止临时预览，恢复该方案设置，再重建相机姿态及最终视差。预览结束恢复平移、偏航及平滑内部状态，不仅恢复画面中的相机变换。自动行走开始可以重置出生点，路线中必须通过实际角色物理移动，不能传送越过建筑、楼梯或河道。

## 交付及边界
